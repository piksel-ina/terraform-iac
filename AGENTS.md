# AGENTS.md — Piksel Infrastructure

Terraform IaC for the Piksel project on AWS (`ap-southeast-3`). Multiple independent Terraform roots; no root-level config.

## Roots

| Root | AWS profile | Apply path | State |
|---|---|---|---|
| `staging/` | `staging-piksel` | **CodeBuild** (triggered by `.github/workflows/deploy.yml`; projects `piksel-tf-plan` / `piksel-tf-apply`) | S3 `piksel-staging-tfstate` (versioned, locked) |
| `dev/` | `dev-piksel` | `make apply-dev` locally | local `dev/terraform.tfstate`; back up with `make backup-dev` |
| `bootstrap/` | per-account | `terraform apply` locally, per workspace | local, committed under `bootstrap/terraform.tfstate.d/` |
| `secrets-management/` | per-account | `terraform apply` locally, per workspace | local, **not** in git (known gap) |

Shared modules (`networks/`, `aws-eks-cluster/`, `aws-database/`, `karpenter/`, `applications/`, `external-dns/`, `aws-s3-bucket/`, `aws-s3-static-hosting/`, `cluster-addons/`, `codebuild/`) are consumed by `staging/main.tf` via `source = "../<module>"`. Moving or renaming a module dir breaks those paths.

## Change workflow

```
make fmt                    # required — unformatted code fails pre-commit
make validate-<env>         # syntax + type check
make plan-<env>             # review plan
# staging: merge/push — CodeBuild applies via deploy.yml
# dev:     make apply-dev && make backup-dev
make pre-commit             # before committing (fmt + docs)
```

New module or provider added? Run `make init-<env>` first.

## Conventions

- **Terraform version** pinned in `.terraform-version`. Provider versions live in each root's `providers.tf` — do not restate them here.
- **Every `variable` and `output` needs `description` and `type`.** No exceptions.
- **Block ordering in resources:** `count`/`for_each` → arguments → `tags` → `depends_on` → `lifecycle`.
- **Block ordering in variables:** `description` → `type` → `default` → `validation` → `nullable`.
- Singleton resources use name `"this"`. Multiple same-type resources use descriptive names.
- Module READMEs are auto-generated by the `terraform_docs` pre-commit hook — never hand-edit them.
- `terraform_validate` hook runs only on `staging/` and `dev/`; `terraform_docs` skips `cluster-addons`, `codebuild`, `aws-s3-static-hosting`, `dev`, `bootstrap` (see `.pre-commit-config.yaml`).
- Kubernetes/Helm/kubectl providers use `aws eks get-token` — `awscli` must be on PATH.
- `*.tfvars` and `*.auto.tfvars` are gitignored. Exception: `dev/dev.auto.tfvars`.
- `dev/.secrets/` holds generated SSH `.pem` keys (gitignored).

## Cluster checks (staging)

`make help` lists them. Scripts in `scripts/` read env from the Makefile. Targets: `check-context`, `check-ami`, `check-versions`, `check-health`, `check-endpoints`, `restart-deployments`, `scan-deprecated`.

## Boundaries

- **Never run `terraform destroy` in any environment.**
- Never edit `.tfstate` files directly — use `terraform state` commands.
- Never move or rename module directories — `source = "../<module>"` paths in `staging/main.tf` will break.
- Staging cross-account role ARNs (hub account `686410905891`) are hardcoded in `staging/providers.tf` and `staging/main.tf` (ExternalDNS, ODC/CloudFront) — changing them breaks DNS and CloudFront.
- `lifecycle { ignore_changes = all }` on dev EC2 instances — Terraform won't see manual changes.
- Roots are independent — there is no root-level Terraform config to init.
